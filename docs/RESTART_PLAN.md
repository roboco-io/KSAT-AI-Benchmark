# 수능 전후 연례 모델 평가 계획 초안

2026-10-12 기준. 기존 평가 방식은 새 실험의 전제로 삼지 않는다. 원본 시험지와 정답표를 다시 검증하고, 입력·풀이·채점·기록을 새로 설계한다. 이번 작업의 범위는 프로젝트 조사와 계획 수립이다. 유료 모델 호출, 구현, 삭제, 커밋, 배포는 포함하지 않는다.

## 목표와 결정할 사항

사용자가 명시한 운영 의도는 다음과 같다.

> 이 프로젝트는 수능 일자에 맞춰서 연도별로 업데이트 하려고해. 수능 전에 작년 문제를 최신 모델로 한번 풀어보고 수능이 실시되면 직후에 다시한번 풀어서 결과를 보자.

매년 **수능 전 전년도 시험 평가 1회**와 **수능 직후 새 시험 평가 1회**를 공식 실행으로 남긴다. 최신 모델의 공개 시험 성과를 연도별로 축적하고, 같은 시험에 대한 모델 발전과 같은 모델의 전년도·새 시험 성과를 함께 살펴본다.

- 성공 기준: 원본과 일치하는 입력, 정확한 채점, 실행 조건과 원본 응답의 보존, 같은 조건에서 다시 실행할 수 있는 평가.
- 확인할 사항: 대상 과목·선택과목, 모델 수, 총 API 예산, PDF 직접 입력과 이미지 입력 중 공식 평가 방식.
- 예산이 정해지기 전에는 대규모 호출 계획을 확정하지 않는다. 모델 접근 권한과 실제 비용은 소규모 호출로 확인한다.

## 연례 운영

| 시기 | 대상 | 운영 방식과 산출물 |
| --- | --- | --- |
| 수능 2~4주 전 — 제안 | 전년도 수능 | 최신 모델 후보의 접근성을 확인하고 입력·설정을 고정한다. 모델별 공식 평가 1회 후 사전 결과를 공개한다. |
| 수능 직후 | 새 수능 | 공식 문제지가 공개된 뒤 확보·검수하고, 사전 평가와 같은 모델·설정으로 공식 평가 1회를 수행한다. 답안 제출 시각과 원본 응답을 저장한다. |
| 공개 정답 기준 채점 | 새 수능 | 최초 공개 정답으로 잠정 점수를 공개하고 정답 버전과 잠정 상태를 표시한다. |
| 최종 정답 확정 후 | 새 수능 | 저장한 모델 답안을 최종 정답으로 다시 채점한다. 모델을 다시 호출하지 않고 확정 결과를 공개한다. |

문제 공개·입력 검수·답안 제출·채점·결과 공개의 시각을 따로 기록한다. 특정 자동 실행 시각이나 예약 작업은 아직 설정하지 않는다.

### 연도별 비교 규칙

- **같은 시험, 다른 시점의 모델:** 전년도 수능 직후 결과와 올해 수능 전 전년도 문제 결과를 나란히 표시한다. 모델 변화뿐 아니라 공개 문제의 학습 가능성도 함께 해석한다.
- **같은 모델, 다른 시험:** 올해 사전·직후 결과를 나란히 표시한다. 시험 난도가 달라 단순 점수 차이를 모델 능력의 증감으로 해석하지 않는다.
- 사전 평가에서 모델 ID·버전·추론 설정·입력 방식·프롬프트·도구 정책·풀이 단위를 고정하는 것을 기본안으로 삼는다. 직후에 새 모델이 출시되면 별도 추가 결과로 표시한다.
- 고정 스냅샷이 없거나 모델이 종료돼 같은 버전을 호출할 수 없으면 그 사실을 표시한다. 대체 모델의 결과를 동일 모델의 결과로 묶지 않는다.
- 기록에는 실행한 달력 연도, 시험 학년도, 수능 전·직후 구분을 모두 둔다. 같은 시험을 다음 해에 다시 평가해도 이전 기록을 덮어쓰지 않는다.
- 예비 호출은 시스템 확인용이다. 공식 실행과 구분하고, 정답을 본 뒤 유리한 결과만 선택해 공개하지 않는다.

### 2026년 운영 대상

2027학년도 수능 시행일은 **2026-11-19**이다. 따라서 올해 사전 평가 대상은 **2026학년도 수능**, 직후 평가 대상은 **2027학년도 수능**이다. 보유한 2025학년도 PDF는 구현 검증용으로 활용하고, 사전 평가용 2026학년도 공식 문제지·최종 정답표는 새로 확보한다. [교육부 2027학년도 수능 시행일 안내](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=294&boardSeq=100526&lev=0&m=020402)

## 현재 프로젝트에서 확인한 사실

| 영역 | 현재 상태 | 새 계획에 주는 의미 |
| --- | --- | --- |
| 데이터 | 2025학년도 국어·수학·영어 문제지와 정답표 PDF, 과목별 YAML | 원본 PDF는 재검증 후 활용한다. 기존 YAML은 정답 데이터로 신뢰하지 않는다. |
| 평가기 | Python, 공급자별 구현 5개, 문항별 텍스트 요청 | 이미지·음성 입력과 최신 추론 설정을 새 인터페이스에서 다룬다. |
| 모델 설정 | 활성 모델은 GPT-5, GPT-4o, Opus 4.1, Sonnet 4.5, Solar Pro 2 | 모델 ID와 공급자별 지원 기능을 실행 시점에 다시 확인한다. |
| 결과 | 시험·모델별 YAML에 점수·풀이 설명·시간 저장 | 같은 경로를 덮어쓰므로 새 실험은 실행별 불변 기록을 사용한다. |
| 공개 | YAML을 JSON으로 변환하고 Next.js 15·Mantine 화면을 GitHub Pages에 배포 | 결과 구조를 확정한 뒤 공개 화면을 별도 개편한다. |
| 검증 | `tests/`에 README만 존재. 루트의 프롬프트 실험 파일은 API 호출 스크립트 | 새 평가기를 검증할 오프라인 테스트가 필요하다. 기존 API 스크립트는 테스트로 실행하지 않는다. |
| 문서 | README·ARCHITECTURE에는 현재 없는 자동 파서와 워크플로우 설명이 남아 있음 | 새 명령과 실제 동작을 기준으로 문서를 다시 작성한다. |

조사 당시 수학 YAML과 수학 결과 5개에 미커밋 변경이 있다. 사용자의 작업으로 취급해 보존한다.

### 기존 결과를 기준점으로 사용하기 어려운 이유

1. **수식이 원본과 다르다.** 수학 PDF 첫 페이지를 이미지로 렌더링해 대조했다. 1번의 원본은 세제곱근과 지수 `1/3`인데 YAML은 제곱근과 `1/2`이다. 2번 원본의 `x^3`도 YAML은 `x^2`로 기록한다. 전체 문항의 오류 비율은 아직 조사하지 않았다.
2. **시험 구성이 섞여 있다.** 수학은 공통 22문항과 선택과목 3종 각 8문항을 합친 46문항·152점으로 요약한다. 선택과목별 시험 점수와 전체 문항 풀의 정답률은 구분해야 한다.
3. **영어 입력과 분모가 불완전하다.** 영어 YAML은 42문항이며 32·37·40번이 없다. 평가기는 질문의 `듣고` 문자열로 건너뛰고, 웹 내보내기는 16번부터 독해로 집계한다. 영역 구분과 제외 기준을 데이터에 명시해야 한다.
4. **모델마다 풀이 지시가 다르다.** GPT-5 분기는 모든 과목에 국어 풀이 전용 시스템 프롬프트를 사용한다. 일부 공급자 프롬프트는 단답형 처리와 충돌하는 `1~5` 답 제한을 포함한다.
5. **실행을 재현할 정보가 부족하다.** 결과 YAML에는 입력 해시, 프롬프트 버전, 추론 설정, 토큰 사용량, 원본 API 응답이 없다. 원본 응답은 디버그 로그에만 남을 수 있다.

이 사실만으로 기존 낮은 점수의 원인을 모델 능력으로 단정할 수 없다.

근거 파일: `src/evaluator/evaluator.py`, `src/evaluator/base_model.py`, `src/evaluator/models/`, `exams/parsed/*.yaml`, `models/models.json`, `scripts/export_data.py`, `.github/workflows/deploy-pages.yml`, `pytest.ini`.

## 접근 방식 비교

| 방식 | 장점 | 한계 |
| --- | --- | --- |
| 원본 PDF 직접 입력 — 연례 운영의 우선 후보 | 수식·도표·밑줄·배치를 보존하고 새 시험 공개 후 준비 작업을 줄임 | 공급자별 내부 처리와 비용이 다르고 답안 누락 여부를 확인해야 함 |
| 원본 이미지 기반 평가 | 동일한 이미지와 해상도로 입력을 통제하기 쉬움 | 문항·공유 지문 영역을 정확히 구성해야 하고 시각 인식 성능도 점수에 포함됨 |
| 검증된 텍스트 기반 평가 | 비용을 줄이고 텍스트 추론을 비교하기 쉬움 | 수식과 시각 정보 전사에 별도 검수가 필요함 |
| 도구를 사용하는 풀이 시스템 | 코드 실행·계산·자가검증으로 최대 성능을 탐색 | 도구와 호출 정책의 효과가 섞이므로 기본 모델 비교와 분리해야 함 |

연례 운영은 새 시험 공개 직후 평가할 수 있어야 하므로 원본 PDF 직접 입력을 우선 후보로 둔다. 보유 PDF의 같은 10문항으로 PDF·이미지 입력의 누락·정확도·비용을 확인한 뒤 사전 평가 전에 방식을 고정한다. 텍스트 전사와 도구 활용은 보조 실험으로 둔다. PDF 직접 입력 지원과 처리 방식은 [OpenAI](https://developers.openai.com/api/docs/guides/file-inputs), [Claude](https://platform.claude.com/docs/en/build-with-claude/pdf-support), [Gemini](https://ai.google.dev/gemini-api/docs/document-processing)의 공식 문서를 기준으로 확인한다.

## 새 평가 설계

### 데이터와 시험 구성

- 원본 PDF의 출처, 학년도, 시행일, 홀수·짝수형, 과목·선택과목, 파일 해시를 기록한다. 학년도와 시행 연도는 별도 필드다.
- PDF를 일정한 해상도로 렌더링해 시각 검수한다. 한국어 PDF 검수는 텍스트 추출로 시작하지 않고 필요시 OCR을 사용한다. 모델 API의 내부 PDF 처리는 별도로 기록한다.
- PDF 직접 입력에서는 시험 또는 공통 지문을 포함한 묶음의 페이지와 문항 번호를 지정한다. 이미지 입력에서는 본문·보기·선택지·도표 영역과 공유 지문의 모든 관련 페이지를 연결한다. 페이지를 넘는 문항과 중복 번호는 과목·선택과목을 포함한 ID로 구분한다.
- 모델 요청에는 시험지 또는 지정한 원본 영역과 공유 지문을 포함한다. 정답표·해설·이전 모델 답변은 풀이 과정에서 접근할 수 없게 한다.
- 정답과 배점은 별도 채점 파일에 둔다. 문항 수·번호·배점 합계·정답 범위·지문 연결·영역 누락을 검증하고 원본과 전수 대조한다.
- 수학은 공통+선택과목별 30문항·100점 시험으로 보고한다. 전체 선택과목 문항을 평가하더라도 시험별 집계에서 분리한다.
- 국어는 공통+선택과목을 명시한다. 영어는 듣기·독해를 명시한다. 음성 확보 전 독해 실험은 독해 점수와 분모를 표시하며 전체 수능 영어 점수로 환산하지 않는다.

### 풀이 조건

- 기본 실험은 동일 입력과 중립적인 공통 지시로 검색·코드 실행·풀이 재시도 없이 문항별 최종 답 1개를 받는다. 시험 전체 요청·지문 묶음 요청·문항별 독립 요청 중 풀이 단위는 예비 실험에서 정하고, 사전·직후에 동일하게 유지한다. 서로 다른 풀이 단위의 결과를 같은 순위에 섞지 않는다.
- 내부 추론을 장문으로 출력하도록 강제하지 않는다. 최종 답과 짧은 설명만 요청한다. 설명은 모델이 제공한 설명이며 내부 사고 과정이라고 표시하지 않는다.
- 객관식 답은 선택지 번호, 수학 단답형은 정수로 검증한다. 숫자 문자열은 정해진 규칙으로만 정규화하고 설명에서 임의로 답을 추측하지 않는다.
- 공급자별 추론 수준·출력 한도·시간 제한을 명시한다. 같은 `high` 명칭이나 토큰 한도가 같은 계산량을 뜻한다고 가정하지 않는다. 품질과 비용을 함께 보고한다.
- 예비 실행 후 조건을 고정한다. 본 평가 오답을 본 뒤 프롬프트를 바꾼 결과는 별도 실험으로 기록한다.
- 확장 실험은 동일한 도구·최대 호출 수·시간·비용 한도에서 수행한다. 검색을 허용하는 실험은 공개 정답 접근 위험 때문에 별도 분류한다.

### 실행과 기록

새 구성은 데이터 패키지 → 실행 조건 → 공급자 어댑터 → 실행기 → 채점기 → 보고서로 나눈다. 기존 평가기와 프롬프트는 재사용하지 않는다.

- 공급자 공식 API를 직접 사용한다. OpenAI는 Responses API를 기준으로 하고 Claude·Gemini도 현재 공식 SDK와 추론 설정을 확인한다.
- 실행마다 고유 ID를 만든다. 데이터 해시, 코드 커밋 및 미커밋 여부, 프롬프트 버전, 요청 모델 ID, 반환 모델 정보, SDK 버전, 모든 설정을 저장한다. 고정 스냅샷을 제공하지 않는 모델은 그 제약을 표시한다.
- 요청·응답·정규화한 답·채점 결과를 분리해 저장한다. API 키와 인증 헤더는 기록하지 않는다. 원본 응답은 API가 실제로 제공한 범위만 보존한다.
- 요청 완료마다 저장하고 중단 후 같은 조건으로 이어간다. 기존 실행을 덮어쓰지 않는다. 재개는 입력·설정 해시가 일치할 때만 허용한다. 전체 답안 요청에서 누락된 문항은 미응답으로 남기며 추가 풀이를 자동 요청하지 않는다.
- 타임아웃·속도 제한·서버 오류는 제한된 재시도를 허용하고 모든 시도를 기록한다. 내용 기반 거부·형식 오류·잘린 응답·오답은 별도 상태로 남긴다. 응답 형식을 고치기 위한 추가 모델 호출은 별도 풀이 정책으로 취급한다.
- 오류를 점수와 함께 공개한다. 고정 평가 분모에서는 미응답을 0점으로 계산하되, 오답·거부·인프라 오류의 수를 분리한다. 인프라 오류가 남은 실행은 불완전으로 표시한다.
- 토큰·추론 토큰·캐시 토큰 등 제공되는 사용량, 호출별 지연과 재시도 포함 지연, 실행 전체 시간, 기준일 가격으로 추정한 비용을 기록한다. 실제 청구액과 추정 비용은 구분한다.
- 공개 시험은 학습 데이터에 포함됐을 수 있다. 전년도 문제는 이미 공개된 시험이라는 점을 표시한다. 직후 평가는 새 시험 공개 후 가능한 한 빨리 수행하되, 공개 시점 이후의 정보 접근·서비스 변경 가능성까지 배제했다고 주장하지 않는다.

## 최신 모델 후보

2026-10-12에 조회한 공식 문서 기준이다. 계정별 호출 가능 여부와 가격은 아직 확인하지 않았다. 아래 후보 전체를 한 번에 평가하지 않고 우선 공급자별 대표 모델 1개로 시작한다.

| 공급자 | 대표 후보 | 추가 비교 후보 |
| --- | --- | --- |
| OpenAI | `gpt-6-astra` | 예산에 따라 경량 모델 추가 |
| Anthropic | `claude-fable-5-1` | `claude-opus-5-5`, `claude-sonnet-5-5` |
| Google | `gemini-3.1-pro-preview` | 안정 모델 `gemini-3.8-flash` |

OpenAI 공식 문서는 GPT-6 Astra를 추론 작업의 시작점으로 안내한다. [OpenAI reasoning models](https://developers.openai.com/api/docs/guides/reasoning)

Claude 공식 목록은 Fable 5.1을 고난도 추론 후보로, Opus 5.5와 Sonnet 5.5도 현재 모델로 제공한다. [Claude models overview](https://platform.claude.com/docs/en/models/overview)

Gemini 공식 목록에서 3.1 Pro는 Preview, 3.8 Flash는 Stable이다. Preview 여부를 결과에 표시하며 실행 중 모델이 변경되면 새 실행으로 분리한다. [Gemini models](https://ai.google.dev/gemini-api/docs/models)

Solar 등 한국어 모델은 사용자가 비교 범위를 정한 뒤 현재 공식 API·이미지 지원·접근성을 확인해 추가한다. Gemini의 과거 차단 기록은 최신 모델의 제외 근거로 재사용하지 않고 예비 실행에서 다시 확인한다.

## 실행 순서와 완료 기준

| 단계 | 수행할 일 | 완료 기준 |
| --- | --- | --- |
| 1. 범위 확정 | 연례 사전·직후 평가의 과목, 선택과목, 모델 3개 안팎, 총예산과 호출 상한 결정 | 평가 조건 문서가 있고 비용 상한을 계산할 수 있음 |
| 2. 수학 예비 데이터 | 보유한 2025학년도 원본에서 쉬운 문항·고난도 문항·도표·단답형을 포함한 10문항 구성 | 이미지·정답·배점을 모두 원본과 대조하고 검증 통과 |
| 3. 최소 평가기 | 새 데이터 스키마, 어댑터, 실행별 기록, 채점기, 재개 기능 작성 | 오프라인 검증과 각 공급자 API 연동 확인 통과 |
| 4. 예비 실험 | 같은 10문항으로 3모델의 PDF·이미지 입력 비교. 출력 한도·거부·형식·비용 확인 | 입력 방식·풀이 단위·조건·예산을 고정 |
| 5. 사전 평가 준비 | 2026학년도 공식 문제지·최종 정답 확보. 수학에서 확인한 구조를 대상 과목에 확장 | 과목별 정답·배점·범위 검수 완료 |
| 6. 사전 평가와 공개 | 최신 모델로 전년도 시험 공식 평가 1회. 실행 기록과 연도별 화면 구축 | 과목·선택과목별 점수, 상태별 건수, 비용·지연과 조건 공개 |
| 7. 수능 직후 평가 | 2027학년도 공식 문제지 공개 후 검수·공식 평가 1회 | 사전 평가와 동일 조건의 답안·원본 응답 보존, 잠정 결과 공개 |
| 8. 확정 결과 | 최종 정답 확인 후 저장한 답안 재채점 | 추가 모델 호출 없이 확정 결과와 수정 이력 공개 |

예비 실험은 3모델×10문항×2입력 방식으로 60개 답안을 비교한다. 실제 요청 수는 풀이 단위에 따라 달라진다. 전송 오류 재시도도 비용 상한에 포함한다. 공식 평가는 시기별 1회이며, 반복 측정은 필요할 때 별도 보조 실험으로 둔다.

2026학년도 시험의 시행일은 2025-11-13이다. 올해 사전 평가에서는 이 시험의 공식 문제지와 최종 정답표를 사용한다. [교육부 시행일 안내](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=294&boardSeq=96215&lev=0&m=020402)

## 검증과 보고

- 데이터: 영역 누락, 공유 지문 누락, 선택과목 ID 충돌, 번호·배점·정답 범위를 검증한다.
- 채점: 객관식과 정수 단답형, 미응답, 거부, 형식 오류를 포함한 고정 사례로 검증한다. 채점 파일이 모델 요청에 들어가지 않는지 확인한다.
- 실행: 속도 제한·타임아웃·불완전 응답을 모의 응답으로 재현한다. 중단 후 재개에서 중복 완료·덮어쓰기가 없는지 확인한다.
- API: 공급자별 객관식·단답형·이미지 문항의 실호출로 인터페이스를 확인한다. 유료 확인은 구현 단계에서 정한 예산 안에서 수행한다.
- 보고: 운영 연도·시험 학년도·수능 전후 구분·정답 확정 상태와 과목·선택과목별 원점수, 정답률, 완료율, 오류 유형, 비용, 지연을 표시한다. 반복 실행을 추가하면 공식 단일 실행과 분리한다. 표준점수·백분위·학생 등수는 원점수만으로 만들지 않는다.

## 전환 원칙

기존 코드·YAML·결과는 역사 자료로 보존한다. 새 구현과 결과는 별도 경로에 두고, 구체적인 디렉터리 구조는 구현 설계에서 확정한다. 기존 파일의 대규모 이동이나 삭제는 이번 계획에 포함하지 않는다.

첫 구현 대상은 **원본 수학 10문항으로 PDF·이미지 입력을 비교하고 채점·비용·원본 응답을 재현 가능하게 남기는 최소 실행기**다. 이후 사전 평가용 2026학년도 자료와 연도별 결과 화면을 준비해 수능 직후에 동일 절차를 반복할 수 있게 한다.
